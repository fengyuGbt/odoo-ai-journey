# Ch9 GUI 智能体 · 在 Odoo 中的落地

> 课程来源：《动手学大模型》Chapter 9
> Odoo 关联：RPA 类自动化、遗留系统集成
> 优先级：★★★ 理解取舍（知道"GUI agent 是什么、何时才需要"）

## 这一章在讲什么

- **GUI Agent**：让多模态模型"看屏幕 → 决定动作 → 操作界面"，自动完成点击/输入/导航
- **课程例子**：微调 Qwen2-VL，让模型操作手机 App
- **技术栈**：视觉理解（看屏幕）+ 动作生成（点哪里）+ 多步规划

> 关键认知：GUI agent 解决的是"**没有 API 的系统**怎么自动化"。
> 而 Odoo 恰恰是 API 非常完整的系统——所以 GUI agent 在 Odoo 场景里基本用不上。

## Odoo 落地场景（怎么选）

| 场景 | 推荐方案 | 原因 |
|---|---|---|
| 操作 Odoo 自己的界面 | **XML-RPC / JSON-RPC API** | 所有模型/方法都能调，稳定、快、可测试 |
| 跨系统：Odoo + 外部网站 | 外部系统有 API 就走 API；没有才考虑 GUI | GUI 脆弱、慢、难维护 |
| 遗留系统（无 API） | GUI agent（兜底） | 唯一值得用 GUI agent 的场景 |

## 工程要点（Odoo 侧）

1. **Odoo 的 API 是它的核心竞争力**：模型化架构（`env['sale.order'].search(...)`）、
   完整外部 API、可编程工作流——这让 Odoo 比很多闭源 ERP 更适合 AI 集成
2. **自动化优先走 API**：稳定、快、可断言（能测）
3. **GUI agent 的代价**：依赖屏幕渲染（改 UI 就坏）、慢、不可靠、难测试——
   只在"没有别的路"时用
4. **课程的价值**：理解 GUI agent 的边界，你就知道什么时候该说不
