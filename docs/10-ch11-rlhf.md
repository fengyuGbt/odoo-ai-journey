# Ch11 RLHF 对齐 · 在 Odoo 中的落地

> 课程来源：《动手学大模型》Chapter 11
> Odoo 关联：无直接场景（训练自己的模型才需要）
> 优先级：★ 扩展认知（理解"模型为什么听话"）

## 这一章在讲什么

- **RLHF（Reinforcement Learning from Human Feedback）**：用人类偏好反馈训练模型，
  让输出更"听话"、更符合预期
- **课程实现**：trl 库 + PPO 算法，训练 GPT-2 生成积极影评
- **流程**：SFT（指令微调）→ RM（奖励模型）→ RL（PPO 优化）

> 关键认知：你现在用的所有云 API 模型，厂商都已经做过对齐了。
> 你感受到的"模型很听话"，就是 RLHF 的结果。

## Odoo 落地场景

**基本没有直接场景**。判断依据：

| 判断 | 结论 |
|---|---|
| 你在 Odoo 里用现成模型 API 吗？ | 是 → 对齐已由厂商完成 |
| 你有自己训练模型的需求吗？（私有化、行业专用） | 几乎没有 → 不需要 RLHF |
| 你需要理解"模型为什么有时固执/讨好/拒绝"吗？ | 需要 → 这章给答案 |

## 工程要点（Odoo 侧）

1. **知道对齐的含义**：模型的行为倾向（拒绝敏感、讨好用户、风格偏好）来自训练时的对齐，
   不是你能通过 prompt 完全覆盖的
2. **API 模型的"性格"**：调不同的 API 模型，等于选择了不同的对齐策略——
   选择模型时把"行为风格"当参数看
3. **别自己训练**：Odoo 项目做 RLHF 属于"用坦克买菜"——成本、数据、GPU 都不具备

## 小结

Ch11 是课程的收官章，给你的是"**大模型全景的最后一格拼图**"：
预训练给能力，SFT 给指令跟随，RLHF 给行为对齐。理解它，
你就完整知道了"你调的那个 API 背后发生了什么"。
