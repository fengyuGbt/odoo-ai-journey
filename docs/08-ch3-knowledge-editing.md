# Ch3 知识编辑 · 在 Odoo 中的落地

> 课程来源：《动手学大模型》Chapter 3
> Odoo 关联：业务知识更新（产品资料、价格、客户信息）
> 优先级：★★★ 理解取舍（知道"为什么别改模型"）

## 这一章在讲什么

- **知识编辑（Knowledge Editing）**：用 EasyEdit 等工具直接修改模型的记忆——
  让模型把一个"错误事实"改成"正确事实"，而不重训
- **典型方法**：ROME（定位并修改 MLP 记忆层）、定位 + 修改 + 校验
- **研究状态**：模型内部机制层面修改知识，仍属研究前沿

> 关键认知：课程展示"改模型记忆"是**研究课题**；生产系统里知识更新
> 的正解是"改数据 + 让模型能查到"，而不是改模型本身。

## Odoo 落地场景（知识过期问题）

业务里模型"不知道"的事每天都在变：

- 客户改了公司名 / 联系人
- 产品停产 / 规格变更 / 价格调整
- 报价规则、审批流程更新

这些信息在 Odoo 里都存在 **PostgreSQL 数据库**中。

## 工程要点（Odoo 侧）——为什么 RAG 是正解

```
业务数据变更（Odoo 数据库）
   → 模型不感知（它只记得训练时的世界）
   → 两种解法：
      A. 知识编辑（改模型参数）—— 研究前沿，生产别碰
      B. RAG（改数据库 + 重索引向量库）—— ✅ 正解
         · 数据源改了，检索结果就变
         · 模型每次都"看到"最新数据
         · 可审计、可回滚、成本低
```

**一句话：ERP 的数据权威在数据库，LLM 只是"读取器"。**
维护好数据库 = 模型知识自动更新（配合 RAG，见工程三件套笔记）。
