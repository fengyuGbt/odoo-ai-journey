# 工程三件套 · RAG / Function Calling / Eval

> 课程《动手学大模型》没讲、但 Odoo 集成开发天天要用的三样东西。
> 这是连接"课程知识"和"生产应用"的桥，优先级高于课程里任何一章。

## 为什么需要这三件套

```
模型只做两件事：理解输入、生成输出
但业务系统需要模型：
  ① 知道你的业务数据   → RAG（检索增强）
  ② 能替你干活         → Function Calling（工具调用）
  ③ 能证明自己没干坏   → Eval（评估）
```

## 1. RAG · 检索增强生成

### 是什么
模型不知道你的业务数据（产品、报价、客户、文档）。RAG 的思路：
**先把相关资料检索出来，塞进 prompt，再让模型回答**。让模型"带着资料说话"。

### 流程
```
用户提问
  → ① 向量化：问题转成向量（embedding）
  → ② 检索：在向量库/数据库里找最相关的 N 段资料
  → ③ 增强：把资料 + 问题拼成 prompt
  → ④ 生成：模型基于资料回答（资料即"证据"）
```

### Odoo 里的做法
| 数据源 | 索引方式 |
|---|---|
| 产品资料（`product.template`） | 定期导出 → 向量化 → 向量库 |
| 文档（`ir.attachment` / documents） | 解析文本 → 切块 → 向量化 |
| 客户/订单（PostgreSQL） | 结构化数据可直接检索，不必全向量化 |

工程要点：
- **向量库选型**：pgvector（PostgreSQL 扩展，Odoo 直接用同一数据库，最省事）
- **数据变更联动**：产品/文档变化 → 重索引该条（Odoo 里可在模型的 `write/create` 钩子里触发）
- **检索质量优先**：先保证"查得到"，再谈"答得准"；答案要求带引用来源
- **和 Ch3 呼应**：知识更新 = 改数据库 + 重索引，模型自然"知道"了

## 2. Function Calling · 工具调用

### 是什么
让模型不只"说话"，而是"**决定调用哪个工具并给参数**"。
例如用户说"查一下 A 客户的未付款订单"，模型输出 `search_orders(customer="A", paid=False)`，
程序执行并返回结果，模型再组织成自然语言回答。

### 流程
```
用户提问
  → ① 模型决定：需要调用哪个工具、参数是什么（结构化输出）
  → ② 程序执行：调用你的 Odoo API（受权限约束！）
  → ③ 结果回填：把执行结果给模型
  → ④ 模型组织最终回答
```

### Odoo 里的做法
- **工具 = Odoo API 的薄封装**：`search_orders`、`get_product_info`、`create_quotation_draft`…
- **白名单最小化**：只暴露必要方法（读为主，写要审批）
- **权限兜底**：LLM 执行也要过 record rules（见 Ch6 笔记）——**模型可以决定调哪个工具，
  但不能绕过权限**
- **安全细节**：参数校验（防注入）、超时、失败重试、操作留痕

## 3. Eval · 评估

### 是什么
一套**可重复执行的测试**，用来回答"这个 agent 改好了还是改坏了"。
没有 eval，agent 开发就是"盲改"。

### 三要素
| 要素 | 说明 |
|---|---|
| 测试集 | 一批带预期行为的输入/场景（正常 + 边界 + 风险） |
| 执行器 | 把测试集跑一遍，收集 agent 输出 |
| 判定器 | 判定每个输出"通过/失败"（规则或 LLM 评分） |

### Odoo 里的做法
- 测试用例存数据：`agent.eval.case` 模型（场景、预期、严重级别）
- 判定：简单场景用规则（关键词/字段匹配），开放场景用另一个 LLM 打分
- 门槛：通过率 < 阈值 → 不允许发布新 prompt（CI 思路）
- 日志：失败样本一键"另存为测试用例"，测试集持续增长

## 组合起来：一个完整 demo（自然语言查客户订单）

```
用户在 Odoo 对话框输入：帮我查 A 客户本月未付款的订单，金额最大的三笔
  → RAG：不需要（结构化查询，直接走工具）
  → Function Calling：模型调用 search_orders(customer="A", month="this", paid=False, limit=3, order="amount desc")
  → 权限：record rule 校验该 LLM 用户能看这些数据
  → 执行 + 回填 + 模型组织回答
  → Eval：测试集里有 5 条同类场景，跑回归确认没退化
```

这个 demo 同时用上三件套，是你学完 Ch2 后的**第一个里程碑任务**。

## 学习建议

| 技能 | 时间 | 方法 |
|---|---|---|
| RAG | 1 周 | 概念 + pgvector + 一个小文档问答 |
| Function Calling | 1 周 | 官方 API 文档 + Odoo 工具封装 |
| Eval | 3-5 天 | 建 10 条用例 + 跑通判定循环 |

三件套学完，你就有能力**验收**豆包写的任何 agent 代码了。
