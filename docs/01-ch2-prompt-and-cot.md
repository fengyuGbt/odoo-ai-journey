# Ch2 提示学习与思维链 · 在 Odoo 中的落地

> 课程来源：《动手学大模型》Chapter 2
> Odoo 关联：全模块通用（agent 地基）
> 优先级：★★★★★ 第一优先
> 状态：✅ 已完成（API 调用 + 零/少样本已实测，见"实测记录"）

## 这一章在讲什么

- **API 调用**：LLM 通过 API 使用，理解 chat completion 的基本调用方式（这也是 Odoo 集成的最常见形态）
- **零样本 / 少样本提示（Zero-shot / Few-shot）**：不给例子直接问 vs 给几个高质量例子再问
- **思维链 CoT（Chain-of-Thought）**：让模型"先想再答"，复杂任务正确率显著提升
- **Self-Consistency**：同一个问题让模型想多次，投票选最一致答案，进一步提正确率

> 关键认知：**提示（Prompt）就是调用 LLM 的"接口"**。你不需要会训练模型，
> 但需要会写提示——就像你会用 SQL 但不写数据库引擎。

## Odoo 落地场景

| 功能 | Odoo 模型 | 一句话说明 |
|---|---|---|
| 产品描述自动生成 | `product.template` | 点按钮，用产品属性生成英文/多语言描述（出海刚需） |
| 询盘邮件回复草稿 | `crm.lead` / `mail.thread` | 根据客户询盘一键起草英文回复 |
| 非结构化 → 结构化 | `crm.lead` / `sale.order` | 把邮件/文本里的关键信息提取成字段（客户、数量、预算） |
| 报价单改写 | `sale.order` | 语气/详略调整，适配不同客户 |

## 工程要点（Odoo 侧）

1. **API Key 管理**：存 `ir.config_parameter`（系统参数），不硬编码，支持多环境
2. **封装 `llm.service`**：一个服务模型统一封装 chat / completion / 工具调用，业务模型只调它
3. **Prompt 模板数据化**：模板存数据库（`ir.model.data` 或独立模型），业务人员可改，不埋在代码里
4. **Few-shot 样本来自你的业务数据**：CRM 里历史成交邮件就是最好的少样本示例（课程讲的是原理，样本要用自己的）
5. **异步化**：Odoo 是同步 WSGI，长调用（生成大段文本）放 `queue_job` / cron，避免卡界面
6. **CoT 用在复杂任务**：多条件报价建议、条款分析这类任务给模型"推理空间"；简单任务直接答
7. **免费 API 必须配重试 + 模型降级**（实测新增）：免费模型高峰期服务端过载返回 429，且连接可能挂起超时——`llm.service` 内置指数退避重试（`llm_service.retries`）和备用模型切换（`llm_service.models`）

## 🛠 实测记录（2026-09-15）

**环境**：Odoo 19（WSL 源码，独立 dev 库 `dev_llm`，端口 8070）；智谱 GLM-4.7-Flash 免费 API；`llm_service` 模块 v0.1。

**1. API 调用 + 基础对话 ✅**
```python
env["llm.service"].chat("你好，请用一句话介绍你自己。", system="你是 Odoo llm_service 的测试助手。")
```
返回正常，system 提示生效。

**2. 少样本 vs 零样本（格式稳定性）✅**
少样本提示给了 2 个"产品：描述"示例后，模型输出与示例格式完全一致：
> 真无线蓝牙耳机，高清降噪，音质纯净。佩戴轻盈舒适，超长续航，通勤运动首选。

结论：**少样本的格式稳定性肉眼可验证**——这正是 Ch2 概念在 Odoo 场景的第一次落地。

**3. 免费 API 限流（真实踩坑）⚠️**
高峰期连续调用返回 `429 / code 1305 / "该模型当前访问量过大"`；且服务端过载时连接建立后可能挂起直到读取超时（TimeoutError）。处理：模块内置重试（指数退避 2s/4s/8s）+ 备用模型切换（`glm-4.7-flash` → `glm-4-flash`）。完整排查过程见 `docs/logs/2026-09-15-llm-service-限流重试.md`。

**遗留**：产品描述按钮（`product_desc_generator`）为下一步；CoT/自洽性（Self-Consistency）实验待 Ch4 推理章节联动验证。
