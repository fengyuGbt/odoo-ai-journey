# Ch8 多模态模型 · 在 Odoo 中的落地

> 课程来源：《动手学大模型》Chapter 8
> Odoo 关联：`ir.attachment` 附件、`purchase.order`、`account.move`、报关/合同管理
> 优先级：★★★★ ERP 刚需（尤其出海业务）

## 这一章在讲什么

- **多模态模型**：同时处理文本 / 图像 / 音频 / 视频，如 NExT-GPT 支持任意模态互转
- **模态对齐**：让不同模态在同一语义空间里"对齐"（CLIP 式的对比学习思想）
- **能力边界**：模型能看图说话、听音转文、图文理解

> 关键认知：多模态模型是**能力**，不是部署目标。Odoo 里你用的是"理解图片/PDF 的能力"，
> 而不是自己部署一个 NExT-GPT（资源门槛太高，工程上不划算）。

## Odoo 落地场景

| 功能 | Odoo 模型 | 一句话说明 |
|---|---|---|
| 发票自动录入 | `account.move` / `purchase.order` | 发票 PDF/图片 → 提取金额、供应商、日期 → 自动建单 |
| 合同条款结构化 | `documents` / `ir.attachment` | 合同扫描件 → 提取关键条款（金额、期限、违约） |
| 报关单识别 | `stock` / 报关模块 | 出海刚需：报关单/装箱单 → 结构化数据 |
| 产品图生成描述 | `product.template` | 根据产品图片生成/校验描述 |

## 工程要点（Odoo 侧）

1. **流水线是核心**：`ir.attachment`（文件进来）→ 调视觉 API（豆包视觉 / OpenAI vision）→
   返回结构化 JSON → 校验 → 写入 Odoo 模型字段
2. **结构化输出**：用 API 的 JSON 输出模式，让模型返回固定 schema，程序直接消费
3. **校验层**：OCR 会错。金额、日期、供应商要二次校验（Odoo 里比对已有主数据），
   置信度低的人工确认——**"机器预填 + 人工确认"是 ERP 场景的标准姿势**
4. **不要自己部署多模态模型**：理解原理（模态对齐）即可，调用云 API 性价比最高
5. **成本控制**：图片 token 贵，先压缩/裁剪，只送必要区域


## 小结

Ch8 对应的是 ERP 里**"纸质/PDF 世界 → 结构化数据"**的刚需。学原理、会调 API、
搭好"预填 + 人工确认"的流水线，这个功能就能直接变成生产力。
