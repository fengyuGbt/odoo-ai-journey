# Ch1 微调与部署 · 在 Odoo 中的落地

> 课程来源：《动手学大模型》Chapter 1
> Odoo 关联：`mail.thread` 消息分类、工单系统（`helpdesk`）、CRM 线索
> 优先级：★★★★ ERP 刚需（重点在理解"训练 vs 推理"）

## 这一章在讲什么

- **HuggingFace 生态**：`transformers` / `datasets` / `pipeline`，加载预训练模型
- **微调流程**：加载数据 → 处理数据 → 加载模型 → 训练 / 验证 / 预测（`run_classification.py`）
- **部署**：Gradio 演示界面，把训练好的模型暴露成可用服务
- 课程例子：BERT 文本分类（正负样本）

> 关键认知：**"训练"和"推理"是两回事**。微调 = 用你的数据调整模型参数（贵、慢、要 GPU）；
> 推理 = 调用模型给出结果（便宜、快）。Odoo 开发里 99% 只用推理。

## Odoo 落地场景

| 功能 | Odoo 模型 | 一句话说明 |
|---|---|---|
| 邮件/工单自动分类 | `mail.thread` 消息 | 客户来信自动打标：销售 / 售后 / 财务 / 投诉 |
| 询盘自动评分 | `crm.lead` | 判断线索质量（高意向 / 低意向） |
| 评论情感分析 | `product.template` 评论 | 差评自动预警 |
| 发票/单据分拣 | `account.move` | 自动识别单据类型 |

## 工程要点（Odoo 侧）

1. **先问"要不要微调"**：通用分类（英语、常见主题）→ 直接调现成 API；只有
   "行业黑话、专有名词特别多、准确率不达标"时才考虑微调
2. **推理放哪**：Odoo 是同步框架，重推理塞在请求里会卡界面 →
   - 小模型：本机加载（CPU 可跑），用 `queue_job` 异步执行
   - 大模型/API：调远程服务，网络请求同样异步化
3. **模型版本管理**：模型不是代码，别塞进 git；固定模型版本/API 版本，更新要走发布流程
4. **失败降级**：模型服务挂了 → 退回人工分类（Odoo 里就是字段默认值 + 队列重试）

## 小结

Ch1 最大的价值是让你建立"训练 vs 推理"的心智模型。在 Odoo 里：
**能调 API 就不自己训，能异步就不同步，有降级才敢上线。**
