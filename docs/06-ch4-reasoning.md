# Ch4 数学推理 · 在 Odoo 中的落地

> 课程来源：《动手学大模型》Chapter 4
> Odoo 关联：补货建议、定价策略、对账异常排查、合同/条款分析
> 优先级：★★★ 理解取舍（判断"代码算 vs LLM 想"）

## 这一章在讲什么

- **推理模型（Reasoning Model）**：像 DeepSeek-R1 这样"先思考再回答"的模型，数学/逻辑任务表现强
- **蒸馏（Distillation）**：用大模型产出的推理数据，训练小模型复现能力（DeepMath 路线）
- **SFT + 推理链**：用"长思维链"数据微调，让模型学会推理过程

> 关键认知：课程展示的是**怎么造一个推理模型**；你在 Odoo 里要做的是
> **判断什么任务值得用推理模型**（直接调 API 即可，自己蒸馏几乎永远不划算）。

## Odoo 落地场景（任务分工）

| 任务 | 正解 | 为什么 |
|---|---|---|
| 库存补货量计算 | 确定性代码（Odoo 模型方法） | 有明确公式，代码算得准、可测试 |
| 多条件报价建议 | 推理模型 API | 开放问题，需要权衡多个约束 |
| 财务对账 | 确定性规则 + 异常标记 | 规则先行，异常才送人工/LLM |
| 合同条款风险分析 | 推理模型 API | 开放分析，输出判断和理由 |

## 工程要点（Odoo 侧）

1. **能用代码算的，绝不用 LLM**：ERP 的核心是确定性（账不能算错），
   LLM 只补"开放分析"的空位
2. **推理模型当工具调**：需要复杂推理时调 DeepSeek-R1 这类 API，带温度调低、给足推理空间
3. **输出要结构化**：推理模型给结论 + 理由 + 置信度，程序可消费、可留痕
4. **自己蒸馏的前提**（几乎不满足）：你有数据、有 GPU 集群、有长期成本优势——
   Odoo 项目基本不会有

## 小结

Ch4 的价值是**分工判断力**：ERP 场景里，确定性优先，LLM 补开放分析，
推理模型只在"真要动脑"时才上场。别在 Odoo 里自己造推理模型。
